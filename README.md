# 아나모픽 디스플레이 실험실

단일 눈 위치에서 기울어진 휴대폰 화면에 표시한 `HELLO`가 고정된 가상 평면의 글자처럼 보이는지 확인하는 **정적 기준선 + 2/3단계 수동·센서 동적 웹 실험**입니다. 기하 계산의 정확성과 실제 착시 경험을 구분합니다. 현재 인간 관찰 결과는 **미측정**입니다.

[공개 GitHub 저장소](https://github.com/neocjmix/anamorphic-display-lab) · [실험 열기 · GitHub Pages](https://neocjmix.github.io/anamorphic-display-lab/)

## 시작

```sh
npm install
npm run dev
npm test
npm run check
npm run build
```

개발 서버가 출력한 주소를 엽니다. `build` 결과는 정적 호스팅용이며 GitHub Pages에 배포할 수 있습니다. GitHub Actions에서 검증 후 HTTPS Pages에 배포합니다.

## 휴대폰에서 실험하기

1. 세로 방향으로 열고, 실험 화면을 가능한 한 크게 표시합니다. 입력 패널이 있는 상태와 실험 화면의 표시 영역을 혼동하지 마세요.
2. **기기 화면 규격**에서 자동 추정 결과를 확인하거나 자신의 기기를 선택합니다. 알려진 화면 규격은 제조사의 픽셀 수와 PPI로 시작 치수를 추정합니다. 브라우저 정보로 정확한 기종을 확정하는 기능은 아닙니다. 미확인 기기는 `68 × 147 mm` 예시값으로 시작하며 자동 크기 적용이 꺼집니다. 정확한 실험에는 자로 **실제로 패턴을 표시하는 사각 영역**을 측정해 직접 입력하세요.
3. **정적 이미지 생성 → 실험 모드 열기**를 누릅니다. 기기 규격 모드에서는 전체 화면 시도 후 실제 표시 영역이 화면에서 차지하는 비율로 치수를 한 번 보정합니다. Safari에서 전체 화면이 지원되지 않으면 브라우저 표시 영역만 사용합니다. 이후 화면 방향·주소창·확대 상태 변화는 경고만 표시하며 이미지를 계속 갱신하지 않습니다. 100% 확대에서 **현재 표시 영역 크기 다시 적용**을 누르거나 직접 측정하세요. 20 mm 눈금도 실제 자와 비교하는 것이 좋습니다. 직접 입력한 가로·세로 및 URL/JSON/관찰 기록에서 불러온 보정값은 자동 추정으로 덮어쓰지 않습니다. 다시 추정하려면 기기 규격 선택을 바꾸세요.
4. 초기 정면 화면 중심을 원점으로 잡고 눈을 `(0, 0, 350) mm`에 둡니다. 한쪽 눈을 편안하게 감고 관찰합니다. 눈의 가로·세로 오프셋도 수동 입력할 수 있습니다.
5. 지지대와 각도 기준을 사용해 화면을 지정한 pivot 주위로 Y축 `30°` 회전시킨 뒤 **멈춥니다**. 실제 회전축과 입력한 pivot이 같아야 합니다. 화면 중심 pivot이라면 중심 위치를 유지합니다.
6. 눈과 화면을 고정한 채 보정된 패턴과 보정하지 않은 기준 패턴을 비교합니다. 글자·테두리의 비례, 가상 평면처럼 느껴지는지, 잘림을 각각 기록합니다.

**정적 모드에서는 움직이며 관찰하지 마세요.** 화면 자세와 눈 위치를 자동으로 추적하지 않습니다. 수동 입력은 실제 자세를 측정하거나 유지해 주지 않습니다. Safari 주소 표시줄 등 browser chrome이 바뀌면 표시 영역과 중심도 달라질 수 있습니다. 전체 화면 요청이 지원되지 않으면 안정된 viewport를 사용하고 그 영역을 교정하세요. 어지럽거나 눈이 피로하면 중단합니다.

## 화면 격자와 평면 격자

- 새 실험은 **화면 격자 10 mm**와 **평면 격자 5 mm**를 함께 표시합니다. 각각 켜거나 끌 수 있으며 간격은 1~1,000 mm로 바꿀 수 있습니다. 입력 패널 변경은 정적 이미지 생성 버튼으로 적용합니다. 실험 모드의 두 격자 버튼은 해당 표시 여부만 즉시 바꿉니다.
- **하늘색 점선**은 실제 표시 영역의 중심 기준 화면 격자입니다. 원본/보정 전환이나 회전각·평면 위치에 관계없이 화면 좌표에 고정됩니다.
- **연두색 실선**은 가상 평면 중심 기준 격자이며 HELLO·테두리와 같은 텍스처에 그립니다. 보정 모드에서 함께 투영되고, 원본 모드에서는 변형하지 않은 표적에 붙어 있습니다.
- 간격은 각 평면의 mm 단위입니다. 화면 격자의 실제 물리적 간격은 표시 영역 보정이 정확할 때만 맞습니다. 가상 평면 격자는 투영 때문에 실제 화면 위에서 간격이 달라지는 것이 정상입니다. 두 격자는 0°·같은 평면에서 겹칠 수 있습니다.
- PNG는 마지막 비교 모드와 적용된 격자를 포함한 전체 표시 영역을 저장합니다. JSON/URL은 입력 패널의 설정을, 관찰 기록은 실제 적용된 설정을 저장합니다. 격자 필드가 없는 기존 버전 1 JSON/URL/관찰 기록은 두 격자가 꺼진 상태로 불러옵니다.
- 두 격자는 동적 실험에서도 유지됩니다. 파란 평면을 켜면 화면 격자는 앞쪽 표적 아래에 가려집니다.

## 동적 실험

정적 이미지 생성 후 **동적 실험 모드**를 여세요. 수동 자세를 먼저 검증한 다음 센서 시작과 기준 자세 저장을 진행합니다. 실제 화면의 파란 평면·불투명도, 앞/뒤 표적의 색상 단서, A/B 정지, 자세/눈 조절, 로그/설정 JSON을 제공합니다. 렌더링은 긴 변 480 px / 최대 15 fps이며 실제 fps를 표시합니다. 가속도 이동은 기본 꺼짐, 오차가 누적되는 XY 추정입니다.

절차·수식·필터·센서 제한·테스트 범위는 [동적 실험 안내](docs/LIVE_EXPERIMENT.md)를 참고하세요.

## 실험 범위

- Phase 0: 좌표·교정·ray/plane 기하 및 오류 처리 검증
- Phase 1: 고정된 눈과 수동으로 고정한 화면 자세에서 정적 지각 비교
- Phase 2: 수동 rigid pose / 눈 위치 조절, 고정 표적 역투영, A/B 정지 비교
- Phase 3: 승인된 브라우저 방향 센서 + 별도 선택하는 실험적 2D 가속도 이동
- 현재 제외: 카메라, 머리/눈 추적, 검증된 6DoF
- Phase 4: 지각 실험 결과와 명시적 승인 이후 iOS feasibility 검토만 수행

이름에 `world-locked`를 사용하더라도 현재 구현은 동작 중 world-lock 안정성을 입증하지 않습니다. 자동 테스트나 스크린샷만으로 사람의 착시 성공을 판정하지 않습니다.

좌표, 투영식, 실패 기준, 기록 양식은 [실험 계획](docs/EXPERIMENT_PLAN.md)을, 화면 규격 근거와 추정 한계는 [기기 화면 보정](docs/DEVICE_CALIBRATION.md)을 참고하세요.

## 검증 상태 (2026-10-09)

Phase 1 구현: 수동 파라미터, 명시적 정적 이미지 생성, 원본/투영 비교, ray 디버그 뷰, 실험 화면, PNG/JSON/URL 저장, 기기 내 관찰 기록 및 설정 재사용. 기존 기준선은 단위 테스트 16개, TypeScript, 프로덕션 빌드 통과입니다. 한국어 UI·기기 규격 추정 변경분의 최종 검증 결과는 배포 시 별도로 확인합니다. 지각적 성공 및 실제 iPhone Safari 관찰은 아직 미측정입니다.

배포 확인: [Phase 1 CI/Pages](https://github.com/neocjmix/anamorphic-display-lab/actions/runs/37890398386) 성공. Cloud Chrome에서 이미지 생성, 원본 전환, 전체 화면 진입/종료, 특이점 차단, URL 복원, 로컬 기록 저장을 확인했습니다. PNG 다운로드 버튼은 구현되어 있으나 cloud browser의 다운로드 완료 이벤트를 받지 못해 파일 저장 완료는 미확인입니다. 실제 iPhone Safari의 저장 동작·표시 영역 교정·지각 결과는 사용자 관찰이 필요합니다.

격자 변경 검증: 단위 테스트 37개, TypeScript 검사와 프로덕션 빌드 통과. RGB 투영 샘플링, 격자 mm 좌표, 원본/보정 화면 격자 고정, 설정 호환성을 자동 테스트합니다. 실제 기기의 물리적 눈금 및 지각 효과는 여전히 미측정입니다.

동적 실험 추가 검증: rigid pose, 센서축·기준 quaternion, XY 가속도 적분과 중단 조건, 정확한 bounded raster, 파란 평면 깊이 합성, 앞쪽 표적의 화면 격자 가림, 동적 설정 복원을 자동 테스트합니다. 최종 테스트 수와 배포 확인은 해당 커밋의 CI를 확인하세요. OP ART 표적(동심원/체커보드)은 자체 애니메이션 없이 같은 투영을 사용합니다. 실제 기기 센서와 지각 검증은 별도입니다.
