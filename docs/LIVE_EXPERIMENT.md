# 2/3단계: 수동 자세와 브라우저 센서 실험

이 단계는 고정된 눈을 가정하는 **실험**이며 눈/머리 추적이나 검증된 6DoF 기능이 아닙니다. 실제 iPhone에서의 센서 정확도, 물리적 눈금, 지각 효과는 아직 미측정입니다. 기존 정적 생성·원본 비교·격자·교정 저장·관찰 기록은 유지됩니다.

## 순서

1. 기존 방식으로 실제 표시 영역, 초기 Y각, pivot, 눈 위치와 표적을 보정하고 정적 이미지를 생성합니다.
2. **동적 실험 모드**를 엽니다. 기기 규격 자동 크기 적용은 정적 실험과 동일합니다. 주소창, 확대, 화면 방향이 바뀌면 치수를 다시 측정합니다.
3. 먼저 센서 없이 수동 피치 X/요 Y/롤 Z 및 x/y/z 이동을 바꿉니다. 수동 회전은 초기 화면 중심 주위의 추가 world 회전입니다. 초기 Y각과 pivot으로 정한 화면 중심은 유지되며 이동만 추가됩니다. 가상 평면과 눈은 고정되고 화면만 움직여야 합니다. 눈 위치는 별도로 수동 조절할 수 있습니다.
4. **A · 현재 이미지 정지**와 **B · 실시간 재개**를 비교합니다. 같은 캔버스, 해상도, 격자, 파란 평면 조건에서 마지막 이미지만 정지합니다. 센서 추정은 A 동안에도 계속되며 B는 현재 자세로 돌아옵니다. 센서 기준이 유효하지 않으면 B를 눌러도 새 이미지를 만들지 않습니다.
5. **센서 권한 요청 · 시작**은 실제 사용자의 클릭에서만 권한을 요청합니다. HTTPS 및 브라우저 지원이 필요합니다. 방향/동작 권한 요청은 첫 await 전에 함께 시작합니다. 권한 거부·미지원·샘플 없음은 수동 모드로 대체할 수 있습니다. 이 앱은 카메라를 사용하지 않습니다.
6. 폰을 입력한 초기 Y각과 화면 중심 위치에 놓고 **기준 자세 / 이동 초기화**를 누릅니다. 기준은 실제 공간을 측정하지 않습니다. 현재 폰 자세가 입력된 초기 자세라는 사용자의 가정입니다. 이후 화면 중심을 유지하며 작은 회전을 시험하세요.
7. 가속도 이동은 기본 꺼짐입니다. 선택하면 기준 위치에서 약 1초간 정지합니다. 먼저 ±5~10 cm 좌우/상하 한 번씩, 다음으로 왕복과 30초 정지 상태를 관찰하세요. 실제 이동거리와 표시된 추정 mm를 비교하세요. 회전 중 중력·기기 bias 오차 때문에 추정이 달라질 수 있습니다. 정확한 위치가 필요한 실험에는 수동 값을 사용하세요.
8. 화면 방향 변경, 페이지 숨김, 오래된 방향 샘플 또는 초기 보정 변경은 센서 기준을 해제합니다. 다시 치수를 확인하고 기준 자세를 저장합니다. 센서 중지 또는 모드 종료 시 이벤트 리스너/렌더 루프가 제거됩니다.

## 실제 화면의 파란 평면 단서

기본 켜짐, 불투명도 40%; 토글과 0–80% 조절이 있습니다. 정확한 광선/평면 교차에서 `target = eye + t(screen-eye)`를 사용합니다.

- `0 < t <= 1`: 표적은 화면보다 앞. 텍스처의 원래 RGB를 유지하며 파란 평면을 가립니다
- `t > 1`: 표적은 화면보다 뒤. `(1-opacity)*targetRGB + opacity*blueRGB`
- 표적이 없는 영역: 검정 배경 위 파란 평면
- 켜진 화면 격자는 평면 위에 그리되, 앞쪽 표적 부분에서는 가려집니다. 평면 격자는 표적 텍스처의 일부입니다
- 표적 직사각형은 검정 부분도 불투명하게 취급합니다. 실제 투명 디스플레이, 양안 입체감, 눈의 이동에 따른 시차를 구현하지 않습니다

색상만 합성하며 표적 좌표·크기·투영식은 바꾸지 않습니다. 회전된 화면이 고정 표적 평면을 가로지르면 앞/뒤가 한 이미지 안에서 나뉩니다. 토글을 끄면 기존 RGB 기준선입니다.

## 기하 및 센서 기준

좌표: mm, x 오른쪽/y 위/z 눈 쪽. 센서는 브라우저의 자연 방향 장치축에서 오른손 intrinsic `Z(alpha) X(beta) Y(gamma)` 순서입니다. 화면 기준 보정은 `S=Rz(-screen.orientation.angle)`.

`D=Rz(alpha)Rx(beta)Ry(gamma)`, `reference=D0*S0`, `relative=reference^-1*D*S`.

기본 Y 회전의 world 행렬이 B라면 실제 화면 방향은 `B*relative`입니다. geometry에 전달되는 world delta는 `B*relative*B^-1`; 초기 pivot으로 만든 화면 중심 주위로 적용하고 world 이동을 더합니다. 기존 JSON의 추가 pose가 있으면 그 방향/이동을 baseline에 포함합니다. 눈과 표적은 자동 갱신하지 않습니다.

Raw 선형 가속도는 `B*reference^-1*D*aDevice`로 world에 옮깁니다. raw 장치 가속도에 화면 방향 S를 다시 곱하지 않습니다. 회전은 브라우저가 제공하는 방향 추정이며 raw gyro를 별도로 적분하지 않습니다. 별도의 각도 저역 필터는 없고 매 렌더링에 가장 최근 방향 샘플을 사용합니다.

## 가속도 이동 필터와 한계

- 브라우저의 유효한 `acceleration` (중력 제외, m/s²)만 사용. `accelerationIncludingGravity` 대체/중력 추측 없음
- 600 ms 및 최소 12개 안정 샘플로 bias 추정. 이는 정지의 증명이 아닙니다. 일정 속도도 가속도 0이므로 구분할 수 없습니다
- bias는 보정 후 고정, 저역 필터 80 ms, deadband 0.08 m/s². 모두 경험적 오차 억제이고 정확도를 보장하지 않습니다
- x/y만 실제 단위로 적분, z=0. 숨은 복원력·위치 자동 0회귀·속도 감쇠 없음
- 반경 150 mm를 넘으려 하면 마지막 범위 내 위치에서 정지하고 초기화 필요. 250 ms 초과 샘플 간격, null/비정상 샘플도 정지. 샘플이 아예 오지 않으면 1.5초 뒤 미지원 상태
- 방향 샘플은 300 ms 이후 투영 갱신 금지, 500 ms 점검에서 기준 해제. 페이지 숨김/화면 방향 변경도 기준 해제
- bias/중력 오차가 두 번 적분되며 변위가 빠르게 틀어질 수 있습니다. 매 짧은 실험마다 명시적으로 초기화하세요. 센서로 절대 위치나 6DoF를 측정한다고 해석하지 마세요

## 렌더링과 기록

Canvas2D의 정확한 inverse homography를 픽셀 중심에서 평가하고 RGB bilinear sampling합니다. CSS perspective나 삼각형 affine 근사 없음. CPU 비용을 제한하기 위해 긴 변 480 px, 목표 최대 15 fps. 실제 fps/프레임 계산 ms/센서 샘플 나이를 표시합니다. 이 ms는 계산 비용이며 광자까지의 전체 지연은 아닙니다. 화면/기기 속도에 따라 15 fps보다 낮을 수 있습니다. 작은 글자는 정적 1800 px 출력보다 덜 선명합니다.

- **동적 설정 저장/불러오기**: 초기 보정, 격자, 수동 자세, 가정한 눈 위치, 파란 평면을 재사용. 항상 센서가 꺼진 수동 모드로 불러오며 센서 기준은 새로 설정합니다
- **실험 로그 JSON**: 최근 최대 2,400개 샘플(약 10분). 실제 그려진 보정과 추정 자세, A/B, 필터 설정/상태, 추정 이동, 계산 시간/fps/샘플 나이. 서버 전송 없음
- 기존 정적 관찰 기록/PNG는 정적 설정과 이미지를 저장합니다. 동적 상태는 반드시 별도의 동적 로그/설정으로 저장하세요

## 검증 범위 및 출처

단위 테스트는 기존 기하/격자 보존, 무작위 rigid pose round-trip, quaternion 순서/화면축/보정 기준, 가속도 합성 입력, bounds/stale/null, 정확한 역투영과 기존 raster 일치, 파란 평면 앞뒤 RGB, 센서 유효성 gate, 설정 호환을 검증합니다. 실제 브라우저 권한, 센서 하드웨어, iPhone 지각 결과는 자동 단위 테스트로 검증되지 않습니다.

## OP ART 표적

동적 조작부의 **표적 무늬**에서 HELLO, 동심원, 체커보드를 선택할 수 있습니다. OP ART의 간격은 가상 평면의 mm이며 2–20 mm 범위에서 조절합니다. 동심원의 원형 비례는 가상 평면에서 유지합니다. 무늬는 자체 애니메이션이나 점멸 없이 같은 정확한 투영과 파란 평면 깊이 합성을 따릅니다. 무늬 종류/간격은 동적 설정 및 로그에 포함됩니다. 고대비 반복 무늬가 불편하거나 어지러우면 중단하세요.
